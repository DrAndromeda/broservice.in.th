## 2. Priority checklist

### P0 — Production crawl and indexability

- [ ] Crawl all 64 sitemap URLs on the live domain; record HTTP status, final URL, redirect chain, content type and indexability.
- [ ] Confirm the live `robots.txt` and `sitemap.xml` match the repository and are reachable without redirects, HTML error pages or access restrictions.
- [ ] Check every sitemap URL returns 200 and is indexable; remove 3xx, 4xx, 5xx, noindex and non-canonical URLs from the sitemap.
- [ ] Verify every page has exactly one absolute self-referencing canonical, except intentional duplicate/alternate pages.
- [ ] Verify reciprocal hreflang for EN, RU, TH and HE on every equivalent page, with valid language codes and x-default. Do not point to missing translations.
- [ ] Check HTTP/HTTPS, www/non-www, trailing-slash and duplicate URL variants; enforce one consistent host and slash policy with one-hop 301 redirects.
- [ ] Check for accidental `noindex`, blocked assets, broken internal links, orphan pages and soft 404s.
- [ ] Rebuild the sitemap after real content changes and update lastmod only for URLs whose content changed.

### P0 — AI crawlers and answer-engine access

- [ ] Add explicit, documented rules for relevant crawlers (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended and CCBot) only according to the owner's intended access policy. Keep the general crawler rule clear.
- [ ] Create a concise `/llms.txt` describing BroService, its verified services, service areas, languages and contact routes. Link only to real canonical pages.
- [ ] Keep the AI-readable description factually aligned with visible page content. Do not invent service guarantees, credentials, prices, reviews, response times or coverage.
- [ ] Confirm `/llms.txt` returns plain text with HTTP 200 and is not blocked by robots, hosting rules or a security layer.
- [ ] Ensure important service information is available in server-delivered HTML, not only in scripts or images.

### P1 — Structured data and entity consistency

- [ ] Consolidate the two homepage LocalBusiness JSON-LD blocks into one stable entity with a single `@id`; align name, URL, telephone, email and areaServed with visible content.

- [ ] Check all 64 pages for valid JSON-LD, unique entity IDs, matching visible FAQ content and correct breadcrumbs.
- [ ] Use Service / FAQPage / BreadcrumbList only where each type matches visible page content and current Google policies.
- [ ] Run Schema.org Validator and Google Rich Results Test on representative live URLs and fix actual errors, not merely warnings.

### P1 — Page-level SEO and content quality

- [ ] Crawl all pages for unique title, meta description, one descriptive H1, language attribute, canonical, Open Graph and image alt text.
- [ ] Check every EN/RU/TH/HE page for correct language, useful translation, correct navigation and equivalent canonical/hreflang mapping.

## 3. Repeatable audit evidence

For every audit run, save a dated report containing:

1. URL inventory and sitemap count.
2. HTTP status and final URL for every sitemap URL.
3. Canonical and hreflang results.
4. Title, description, H1, language and robots results.
5. JSON-LD parse results and duplicate entity IDs.
6. Internal link, image and orphan-page findings.
7. Mobile/accessibility/performance results, with test device and date.
8. Exact fixes made and the URLs re-tested.

Do not mark production verified from repository inspection or a local file alone. A check is complete only when the live URL was tested and the evidence is recorded.
